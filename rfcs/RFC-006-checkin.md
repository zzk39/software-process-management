# RFC-006：到场签到（A6）

- **对应章节**：story.md 六、学生端：签到与履约
- **负责人**：林佳航
- **迭代**：1（Web 动态码）；2（二维码）
- **状态**：Draft

## 1. 背景与目标

到场签到是履约的关键闭环。必须绑定"教室 + 当日动态码 + 时间窗口"，防止代签和异地签到。

## 2. 用户故事

| ID | 故事 | 迭代 |
|---|---|---|
| A6.1 | 到达自习室后签到 | 1 |
| A6.2 | Web 端输入动态编码签到 | 1 |
| A6.3 | 微信端扫描二维码签到 | 2（本项目不做小程序，用 Web 展示二维码，手机浏览器扫） |
| A6.4 | 仅在预约时间附近可签到（±15min） | 1 |
| A6.5 | 校验签到所在教室与预约教室一致 | 1（动态码按 Room 绑定） |
| A6.6 | 签到成功看到"已签到"和时间戳 | 1 |
| A6.7 | 签到失败给出明确原因 | 1 |
| A6.8 | 教室动态码每天更新 | 1（C1.7 调度器） |
| A6.9 | 签到后座位状态变为"使用中" | 1（由 Reservation.status 驱动查询） |

## 3. 数据模型

```python
class Room:
    daily_checkin_code: str    # 当日有效 6 位 hex
    checkin_code_date: str     # YYYY-MM-DD
```

## 4. API 设计

### POST `/api/checkin`

入参：
```json
{ "reservation_id": 10, "code": "A1B2C3" }
```

校验顺序：

| 步骤 | 校验 | 错误 |
|---|---|---|
| 1 | 预约存在且归属本人 | 404 `预约不存在` |
| 2 | `status == PENDING` | 400 `当前状态不可签到` |
| 3 | `now ∈ [start_at - 15min, start_at + 15min]` | 400 `不在签到允许时间窗口内` |
| 4 | `Room.daily_checkin_code == code` | 400 `签到编码错误或已失效` |

成功返回：
```json
{ "code":0, "data":{"reservation_id":10, "checkin_at":"2026-04-12T19:02:33"} }
```

副作用：`Reservation.status = CHECKED_IN`, `checkin_at = now`。

## 5. 前端交互

- `/my` 列表中 PENDING 条目有【签到】按钮
- 点击后弹 Modal：输入 6 位编码 → 确认
- 错误以红字展示详细 `message`
- 成功后卡片状态自动刷新为 `已签到 19:02`

## 6. 验收标准

- [x] 预约 19:00，在 18:40 尝试签到返回 400（早于窗口）
- [x] 预约 19:00，在 19:20 尝试签到返回 400（晚于窗口）
- [x] 用错的动态码返回 400
- [x] 已签到状态再次签到返回 400
- [x] 每天 00:05 调度器刷新动态码后，昨日的 code 立即失效

## 7. 非目标

- 不做硬件对接（门禁/摄像头）
- 不做二维码防重放 nonce（迭代 2 再做）

## 8. 依赖与风险

- 依赖：RFC-004（Reservation）、RFC-017（动态码每日刷新任务）、RFC-011（Room 字段扩展）
- 风险：签到窗口 ±15min 必须与 RFC-017 的自动违约 cutoff 保持一致（都依赖 `checkin_grace_minutes` 参数）
