# RFC-001：学生身份与访问范围（A1）

- **对应章节**：story.md 一、学生端：账号与身份识别
- **负责人**：学生A
- **迭代**：1（简化版：学号密码）；2（对接统一身份认证）
- **状态**：Draft

## 1. 背景与目标

学生进入系统后应基于"身份 + 院系"限定其可操作的资源范围（全校自习室 + 本院系专属自习室）。第一阶段用最小可用登录实现，第二阶段替换为学校统一身份认证（CAS/OAuth2）。

## 2. 用户故事（逐条对齐 story.md A1.1–A1.7）

| ID | 故事 | 迭代 |
|---|---|---|
| A1.1 | 作为学生，使用学校统一身份认证登录，以便不必单独注册 | 1 简化为账号密码；2 接 CAS |
| A1.2 | 系统自动识别院系信息，只看到有权使用的院系自习室 | 1 |
| A1.3 | 首次登录自动绑定学号/姓名/院系，后续预约无需重复填写 | 1 |
| A1.4 | 个人主页可查看基础信息 | 1 |
| A1.5 | 系统明确告知哪些全校开放、哪些是院系专属 | 1 |
| A1.6 | 尝试预约无权限自习室时收到明确提示 | 1（预约链路已做 403） |
| A1.7 | 小程序与 Web 同一账号数据，跨端一致 | 2（本项目仅 Web，但账号模型统一） |

## 3. 数据模型

```python
class User:
    id: int
    student_no: str        # 学号（唯一）
    name: str
    department: str        # 院系，空串视为通用
    password_hash: str     # 迭代 2 后可能改为 oauth_sub
    is_admin: bool
    violation_count: int
    created_at: datetime
```

## 4. API 设计

| 方法 | 路径 | 入参 | 出参 | 说明 | AC |
|---|---|---|---|---|---|
| POST | `/api/auth/login` | `{student_no, password}` | `{access_token, user}` | 签发 JWT，24h 有效 | A1.1, A1.3 |
| GET | `/api/auth/me` | — | `User` | 当前用户基础信息 | A1.4 |
| GET | `/api/rooms` | — | `Room[]`（自动按 department 过滤） | 仅返回本院系可见自习室 | A1.2, A1.5 |

JWT payload：`{sub: user_id, is_admin, exp}`。

## 5. 前端交互

- `/login`：学号 + 密码
- 顶部导航栏：展示 `姓名（院系）`
- 个人中心：展示学号 / 院系 / 累计违约次数

## 6. 验收标准

- [x] 错误学号/密码返回 401 并提示"学号或密码错误"
- [x] 登录成功后 `/api/rooms` 不返回其它院系的专属自习室
- [ ] 页面右上角正确展示 `姓名（院系）` 徽标
- [ ] 无 token 访问受保护接口返回 401，前端自动跳转登录页

## 7. 非目标

- 不实现用户注册（账号由管理员灌库或 CAS 同步）
- 不实现忘记密码（迭代 2 再做）
- 小程序登录（课程不做小程序）

## 8. 依赖与风险

- 依赖：无（底座）
- 风险：迭代 2 接 CAS 时 `password_hash` 字段需兼容缺省；建议未来新增 `auth_provider` 字段
