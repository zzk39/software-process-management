# RFC-009：智能助手（A9）

- **对应章节**：story.md 九、学生端：智能助手
- **负责人**：学生C
- **迭代**：2（规则版）；后续可升级 LLM
- **状态**：Draft

## 1. 背景与目标

通过对话式交互完成查空座、按条件筛选、个人信息查询、规则问答等高频任务，降低多页跳转成本。**课程考核的"智能化"重点之一**。

## 2. 用户故事（保留原 AC）

### Story 9.1 自然语言空座查询
- 输入 `今天晚上还有空座吗` → 返回对应时段空座
- 识别时间信息并转检索条件
- 查询结果以结构化形式返回
- 不需要进筛选页

### Story 9.2 条件化座位筛选
- `帮我找靠窗的座位` → 返回靠窗
- `图书馆带插座` → 多条件组合
- 无结果时明确提示
- 展示核心信息便于决策

### Story 9.3 查询结果结构化展示与直接预约
- 卡片/列表展示
- 含座位号、教室名、可用时间
- 每条"立即预约"
- 座位不可用给明确提示

### Story 9.4 个人当日预约与历史行为查询
- `我今天订了哪里` → 当天预约
- `我有没有违约记录` → 个人违约
- `我最常去哪个自习室` → 个人统计
- 不返回其他用户的信息

### Story 9.5 时间表达与属性关键词理解
- 识别 `今天晚上 / 明天下午 / 现在`
- 识别 `靠窗 / 带插座 / 图书馆 / 安静`
- 正确映射到内部检索条件
- 无法识别时请用户补充说明

### Story 9.6 不明确问题的追问引导与替代建议
- 只说 `帮我找座位` → 追问时间/地点/条件
- 条件不明 → 主动追问
- 无结果 → 放宽条件的建议
- 可基于建议继续

### Story 9.7 规则问答与渐进式智能升级
- 基础：关键词/规则问答
- 保留 LLM 升级扩展接口
- 输出风格一致
- 超纲时给兜底

## 3. 架构

```
用户输入 ─► Intent 识别器 ─► Entity 抽取 ─► Dispatcher ─► 内置技能函数 ─► 结构化回复
             (规则 / LLM)         ↓                       ↓
                              Slots 不全 ──► 追问模板      查询数据库
```

**Intent 类型**：
- `find_seat`（9.1, 9.2）
- `my_today` / `my_violations` / `my_frequent`（9.4）
- `rule_qa`（9.7）
- `unknown`（兜底）

**Entity 类型**：
- `time_range`: 今天晚上 → (18:00, 22:00)；现在 → (now整点, +2h)；明天下午 → (tomorrow 13:00, 18:00)
- `location`: 图书馆 / 光华楼 / 计算机楼
- `attribute`: 靠窗 / 插座 / 安静
- `department`: 本院 / 计算机学院

## 4. API 设计

### POST `/api/assistant/chat`

入参：
```json
{ "session_id": "uuid", "message": "今天晚上有靠窗位子吗" }
```

响应（统一结构）：
```json
{ "code":0, "data":{
  "intent": "find_seat",
  "reply_text": "为你找到 3 个今晚 19-22 点空闲的靠窗座位：",
  "cards": [
    {"type":"seat", "seat_id":3, "code":"01-003", "room":"图书馆3F",
     "available":"19:00-22:00", "actions":[{"type":"book","label":"立即预约"}]}
  ],
  "follow_ups": ["换成带插座的", "改成明天下午"]
}}
```

**技能接口**（纯后端函数，复用已有 API）：
- `skill_find_seat(time_range, attrs) → Seat[]`
- `skill_my_today(user) → Reservation[]`
- `skill_rule_qa(topic) → str`（读 RFC-015 参数动态生成）

## 5. 前端交互

- 右下角气泡按钮，点击展开聊天窗口
- 消息气泡 + 卡片混排
- 快捷推荐（follow_ups）以 chip 形式展示在输入框上方
- 卡片上"立即预约"直接调 RFC-004 API

## 6. 验收标准

严格对齐 story.md 9.1–9.7 每条 AC。举例：

- [ ] 输入"今天晚上" → 返回卡片的时间窗口落在 18:00-22:00
- [ ] 输入"靠窗" → 所有返回卡片座位 `near_window=true`
- [ ] 输入"我有没有违约" → 仅返回该用户的违约统计
- [ ] 非法输入"你好" → 进入 rule_qa 兜底或引导
- [ ] 同一 session_id 上下文保留（用于追问"换成带插座的"）

## 7. 非目标

- 迭代 2 仅规则版（正则 + 关键词词表）
- 不强制接入 LLM；若接入 LLM（DeepSeek/通义/Claude），仅替换 Intent/Entity 抽取层，下游技能函数不变

## 8. 依赖与风险

- 依赖：RFC-002/003/004/005 的查询 API
- 风险：
  - 时间表达歧义（`下午` 是 13:00 还是 14:00）需在 `entity_time.py` 中约定
  - 规则版覆盖率有限，超纲问题必须给兜底而非空回复
  - Session 存储用内存字典即可（迭代 2 规模小）
