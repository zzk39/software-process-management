# RFC-002：浏览自习室与座位（A2）

- **对应章节**：story.md 二、学生端：浏览自习室与座位
- **负责人**：学生A
- **迭代**：1（列表 + 基础详情）；2（座位分布图 + 未来时段）
- **状态**：Draft

## 1. 背景与目标

学生浏览"有哪些资源可用"，从自习室级别下钻到单个座位，得到做预约决策所需的全部可视信息。

## 2. 用户故事

| ID | 故事 | 迭代 |
|---|---|---|
| A2.1 | 查看当前开放的自习室列表 | 1 |
| A2.2 | 查看每个自习室的开放时间 | 1 |
| A2.3 | 查看每个自习室剩余空座数 | 2 |
| A2.4 | 查看位置、楼栋、楼层 | 1 |
| A2.5 | 查看某自习室座位分布图 | 2 |
| A2.6 | 查看座位编号 | 1 |
| A2.7 | 查看座位是否靠窗 | 1 |
| A2.8 | 查看座位是否带固定/移动导轨插座 | 1 |
| A2.9 | 查看座位当前状态（可预约、已预约、不可用、停用） | 1（四态文案） |
| A2.10 | 查看某座位未来一段时间可预约时段 | 1 |
| A2.11 | 区分普通教室 / 图书馆自习室 / 其他区域 | 2（增加 room.type 字段） |
| A2.12 | 通宵开放自习室有明显标记 | 1（字段 `is_overnight` 已有） |

## 3. 数据模型

迭代 1 无新增；迭代 2 需补：

```python
class Room:
    type: str          # "classroom" | "library" | "other"   (A2.11)

# 座位剩余空座可由实时 JOIN reservations 算出，不加字段
```

## 4. API 设计

| 方法 | 路径 | 入参 | 出参 | 用户故事 |
|---|---|---|---|---|
| GET | `/api/rooms` | — | `Room[]`（带 `available_seats`） | A2.1~A2.4, A2.12 |
| GET | `/api/rooms/{id}` | — | `Room` 详情 | A2.2, A2.4 |
| GET | `/api/rooms/{id}/seats` | — | `Seat[]`（每项带 `status`） | A2.5~A2.9 |
| GET | `/api/seats/{id}/slots?date=YYYY-MM-DD` | 查询日期 | `{hour:int, available:bool}[]` 24 小时位图 | A2.10 |

座位实时 `status` 取值：`AVAILABLE | BOOKED | IN_USE | DISABLED`。

## 5. 前端交互

- `/rooms` 卡片列表：名称 + 楼栋楼层 + 开放时间 + 通宵标记 + 剩余空座
- `/rooms/:id` 详情：左侧信息，右侧座位网格（5×N），点击座位展开 24 小时时段色带
- 座位图例：🪟 靠窗、🔌 插座、灰色=不可用、蓝色=选中

## 6. 验收标准

- [ ] 列表按自习室打开状态过滤，停用的不出现
- [ ] 院系专属自习室仅对本院系学生可见（由后端过滤，回归 A1.2）
- [ ] `available_seats` 与真实并发预约一致（提交一次预约后列表数字 -1）
- [ ] `/slots` 返回今日起未来 7 天内每小时的可预约状态

## 7. 非目标

- 不做座位拖拽布局编辑（属于 B3 管理端）
- 不做地图定位

## 8. 依赖与风险

- 依赖：RFC-001 (身份过滤)、RFC-011 (自习室登记)
- 风险：座位实时状态若现场并发高需考虑缓存，一阶段先直接查库
